# AdDock 제품 요구사항

**구현 계약 v0.3 · 2026-11-11**

애드독은 마케팅 대행사가 광고주별 랜딩페이지를 만들고, 방문자의 문의를 받아 후속 상담을 관리하는 SaaS다. 첫 번째 파일럿의 목표는 대행사 가입부터 공개 문의 접수와 상담 상태 변경까지 한 팀이 실제로 수행할 수 있게 하는 것이다.

## 사용자와 권한

대행사 회사·광고주 회사와 계정을 분리한다. 대행사 계정, 광고주 계정, 시스템 운영 계정은 각각 agency_users, client_users, admin_users에 저장한다. 기능별 대상 정책과 공통 권한그룹, 데이터 범위를 조합한다. [계정·권한 명세](07-permissions.md)를 적용한다.

| 대상 | 기본 그룹과 범위 |
| --- | --- |
| 대행사 직원 | 팀장: 대행사 전체 관리. 마케터: 담당 광고주 실무 |
| 광고주 계정 | 광고주: 연결된 회사·랜딩·문의 조회. 대행사가 그룹 권한을 조정 가능 |
| 시스템 계정 | 모든 대행사를 대상으로 부여된 기능만 사용 |
| 공개 방문자 | 로그인 없이 게시된 페이지와 문의 접수 |

대행사 생성 시 팀장·마케터·광고주 그룹을 자동 생성한다. 소속별 그룹은 하나이며 그룹 이름은 권한 판정에 사용하지 않는다. 마지막 유효 관리자와 권한 회수 경쟁을 검사한다. 문의 조회 권한은 상세 응답 원문 조회를 포함한다. audit_logs는 이번 범위에서 제외한다.

## 첫 출시 범위와 수용 기준

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| MS-01 | 로그인과 대행사 전환 | 사용자는 본인의 활성 소속만 볼 수 있다. 같은 계정으로 A 대행사에서는 운영, B 대행사에서는 조회를 할 수 있다. 소속을 잃은 직후 새 요청에는 해당 권한을 사용할 수 없다. |
| MS-02 | 광고주 등록과 관리 | 등록·수정 권한을 부여받은 계정이 활성 대행사에 광고주 이름을 등록·수정할 수 있다. 광고주와 랜딩의 소속은 다른 대행사로 이동할 수 없다. |
| MS-03 | 랜딩과 문의폼 편집 | 광고주별로 랜딩을 여러 개 만들 수 있다. 랜딩마다 문의폼 하나를 둔다. 저장 전 화면 미리보기를 제공하고 제목, 본문, 이미지 URL, 링크, 문의폼 블록을 편집한다. 폼은 텍스트, 긴 텍스트, 이메일, 전화 필드를 지원하며 필드 필수 여부와 안내 문구를 설정할 수 있다. 두 사람이 같은 초안을 편집하면 오래된 저장은 충돌로 표시한다. |
| MS-04 | 게시와 게시 중단 | 게시 버튼을 누른 시점의 저장된 초안을 작업으로 등록하고 진행 상태를 보여준다. 첫 게시 성공 후 서비스 공용 주소가 열린다. 재게시 중이나 실패한 경우 기존 버전을 계속 보여준다. 게시 중단 후 공용 주소와 새 문의 접수를 닫는다. |
| MS-05 | 문의 접수 | 방문자는 로그인 없이 유효한 응답과 동의를 제출할 수 있다. 성공하면 접수 확인 번호를 표시한다. 전송 재시도에는 같은 키를 쓰고 같은 번호를 받는다. 폼이 바뀌어 접수가 거절되면 새로고침 안내를 표시한다. |
| MS-06 | 문의 조회와 상담 처리 | 팀원이 최신순 목록을 광고주·랜딩·상태로 필터링하고 당시 폼 문구와 응답을 본다. 운영 권한이 있는 팀원은 상태를 변경할 수 있고 변경한 사용자와 시간이 기록된다. 동시에 수정하면 나중 요청에 충돌을 표시한다. |
| MS-07 | 대행사 데이터 격리 | A 소속만 있는 계정은 B의 광고주·랜딩·문의 ID를 알아도 조회하거나 변경할 수 없다. 서로 다른 대행사의 ID를 섞은 저장 역시 거절한다. |

공개 흐름은 **대행사 생성 → 광고주 등록 → 랜딩 편집과 게시 → 방문자 문의 접수 → 관리자 조회와 상담 처리** 순서로 데모한다. 초안 저장과 공개 화면 변경은 서로 다른 동작이다. 게시 중단과 새 게시 이후에도 이전 문의는 접수 당시 폼 문구로 확인할 수 있다.

문의 상태는 `NEW → IN_PROGRESS → CLOSED` 순서로 바꾼다. 추가 상담이 필요하면 `CLOSED → IN_PROGRESS`로 재개한다.

## 다음 출시 범위

공용 URL로 파일럿을 끝낸 뒤 기본 방문 분석을 추가한다. 공개 랜딩의 방문 세션과 문의를 광고주·랜딩·일자별로 집계한다. 파일럿 이후 분석 지표 후보는 순 방문 세션, 접수 건수, 문의를 한 세션의 비율이다. 세션 중복 제거 기준, 집계 시간대, 동의와 수집 범위를 정한 뒤 수집 계약을 확정한다.

커스텀 도메인과 자동 DNS 등록, 광고 플랫폼 연동, A/B 테스트, 보고서 자동화, 결제는 이후 범위다.

## 파일럿 통과 기준

테스트용 대행사 두 개로 MS-01~07을 재현한다. 정상 흐름 외에 게시 실패, 이전 폼 제출, 같은 요청의 동시 재전송, 다른 대행사 ID 사용, 마지막 권한 관리자 변경 거절을 각각 확인한다. 실제 문의를 받기 전에 문의 항목과 동의 문구, 열람 및 삭제 절차, 보관 기간을 확정한다. 파일럿 운영 지표로 게시 성공·실패 수, 문의 접수 성공·실패 수, 중복 재전송 수를 기록한다.

공용 주소 우선, 권한그룹, 랜딩당 폼 1개, 문의 상태와 기본 방문 분석의 출시 순서는 v0.1에서 제안한 기준이다. 운영 목표 수치와 실제 고객 파일럿 일정은 팀에서 정한다.
