# 학습하고 기록하는 방법

[위키 목차](README.md)

## 한 번의 학습 흐름

1. **질문하기:** 구현 중 막힌 장면을 적는다. 예: “광고주 등록 요청은 어디에서 권한을 확인할까?”
2. **이해하기:** 개념 노트에 필요한 이유, 요청 흐름, 헷갈린 점을 정리한다. 필요한 경우 Mermaid 그림을 그린다.
3. **설명하기:** 문서를 덮고 내 말로 설명한다. 막힌 부분을 다시 질문한다.
4. **확인하기:** 코드·설정을 찾아 연결하고, 실험 문서에 예상 결과부터 적은 뒤 실행한다.
5. **반영하기:** 관찰 결과로 개념과 아키텍처를 수정한다. 기술을 선택한 경우 ADR에 이유를 기록한다.

그날의 질문과 다음 할 일은 `sessions/YYYY-MM-DD-topic.md`에 남긴다. 세션마다 같은 개념 설명을 복사하기보다 기존 개념 노트를 갱신하고 링크한다.

## 문서 종류별로 남길 것

| 상황 | 기록 위치 | 예시 |
| --- | --- | --- |
| 용어·동작 원리를 새롭게 배웠다 | `concepts/` | NAT는 외부 API 응답을 어떻게 돌려줄까? |
| 코드나 배포 구조가 달라졌다 | `architecture/` | Vite 프록시에서 Traefik으로 진입점 변경 |
| 대안을 비교하고 기술을 선택했다 | `adr/` | 왜 이 환경에서 Traefik을 쓰기로 했는가? |
| 명령이나 UI로 직접 확인했다 | `labs/` | Pod 하나가 사라질 때 오류와 복구 시간 |
| 오늘 무엇을 공부했는지 남긴다 | `sessions/` | 질문, 바뀐 문서, 미해결 항목 |

새 문서는 [템플릿](../imported-learning.md#원본%20양식)을 복사한다. 개념 파일은 소문자 영문과 하이픈, ADR은 `NNN-topic.md`, 세션은 날짜를 포함한 이름을 쓴다. 새 주제를 추가하면 [목차](README.md)에도 연결한다.

## 상태를 올리는 기준

학습, 구현, 실험은 각각 따로 표시한다.

| 구분 | 상태 | 기준 |
| --- | --- | --- |
| 학습 | 학습 중 | 정리하거나 질문하는 단계 |
| 학습 | 이해 완료 | 학습자가 문서 없이 필요성과 흐름을 설명하고 복습 질문에 답함 |
| 구현 | 미구현 / 설계 초안 | 관련 실행 코드나 설정을 아직 확인하지 못함 |
| 구현 | 코드 확인 | 구현 파일과 설정을 직접 확인함. 실행 성공을 뜻하지 않음 |
| 실험 | 미실행 | 절차와 예상만 있음 |
| 실험 | 진행 중 / 실패 / 일부 확인 | 실행했지만 목표를 전부 검증하지 못함 |
| 실험 | 실제 검증 완료 | 환경·명령·실제 결과·근거를 남겼고 그 실험의 통과 기준을 충족함 |

“실제 검증 완료”는 기록한 환경과 시나리오에만 적용한다. 로컬 실험 성공이 운영의 안정성까지 증명하지는 않는다. AI는 사용자의 이해 상태를 대신 확정하지 않는다.

ADR은 `제안 → 채택 / 보류 / 폐기`로 관리한다. 코드에 이미 반영됐지만 당시 결정 과정이 남아 있지 않은 경우 `현행 구현 기록`으로 작성하고, 이유를 추론했다면 명시한다. 기존 결정을 바꾸면 새 ADR에서 이전 문서를 연결하고 이전 상태를 `대체됨`으로 갱신한다.

## 대화가 끝날 때 사용할 요청

```text
오늘 마케스트림을 개발하며 나눈 내용을 markestream/docs에 반영해 줘.
먼저 docs/README.md, docs/learning-guide.md와 관련 기존 문서를 읽어 줘.

개념은 왜 필요한지, 요청 흐름, 내가 헷갈린 점, 마케스트림 적용 방법,
문서를 보지 않고 답할 복습 질문까지 정리해 줘.
같은 주제는 기존 노트를 갱신하고, 새로 생긴 주제만 파일을 만들어 줘.
실제 코드·설정 경로와 확인한 공식 자료를 연결해 줘.

확정한 기술 선택은 ADR에, 실행한 실험은 labs에 기록해 줘.
제안과 채택, 코드 확인과 실제 실행 결과를 구분해 줘.
실행하지 않은 실험은 미실행으로 두고 결과를 만들어 넣지 마.
내가 직접 설명하지 않은 개념을 이해 완료로 바꾸지 마.

오늘 날짜의 sessions 문서에 바뀐 문서 링크와 다음 질문을 정리하고,
docs/README.md의 목차도 갱신해 줘.
```

다른 채팅에서 이어갈 때는 위키 목차와 관련 문서 경로를 알려준다. 접근할 수 없는 대화의 내용을 이미 읽었다고 가정하지 않고, 필요한 질문·답변을 전달받아 반영한다. 이 폴더가 다른 채팅을 자동으로 수집하거나 동기화하지는 않는다.

## 10분 복습

- 다음 날: 그림을 보지 않고 사용자 요청이 DB에 도착하는 흐름을 그린다.
- 3일 뒤: “인증 토큰이 없으면?”, “Pod 하나가 죽으면?” 같은 상황을 설명한다.
- 일주일 뒤: 실제로 확인 가능한 실험 하나를 하고 예상과 관찰의 차이를 기록한다.

횟수를 채우기보다 설명이 막힌 질문을 다음 학습 주제로 삼는다. 복습 날짜와 내 답은 개념 노트 아래에 남긴다.

## 문서 변경을 확인하는 방법

아래는 마케스트림 저장소 루트에서 실행하는 읽기 전용 확인 명령이다.

```bash
git status --short -- docs README.md
git diff -- docs README.md
```

새 파일의 본문은 편집기에서 함께 확인한다. 커밋할 때는 이번 학습과 관련된 파일을 선택하고, 다른 개발 작업과 섞이지 않도록 변경 목록을 확인한다. 토큰·비밀번호·실제 고객 정보는 실험 증거에서 제거한다.
