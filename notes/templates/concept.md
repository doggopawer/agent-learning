# 학습 주제

## 질문과 필요성

공통 개념인지 프로젝트 적용인지 구분한다. 어떤 업무나 코드에서 이 질문이 생겼는가?

## 원리와 요청 흐름

입력, 판단, 저장, 결과를 실제 파일과 연결한다.

## 비즈니스 규칙

누가, 어느 회사의, 어떤 데이터를, 어떤 조건에서 다룰 수 있는가?

## 실제 코드 근거

적용 사례가 있으면 프로젝트 ID·경로와 프로젝트 노트를 연결한다. 저장소 기준 경로, 메서드, 파일 확인일과 지문을 기록한다. 파일만 존재한다고 읽고 이해한 것으로 기록하지 않는다.

## 설계 근거

관련 명세·ADR의 내용을 연결하고 자신의 해석은 따로 적는다.

## 내 말로 설명하기

### 내가 이해한 내용 — 원문

사용자가 자기 말로 정리하기를 기다리는 중이다. 실제 표현을 출처와 함께 보존하고 대신 만들어 넣지 않는다.

### 표현을 다듬은 버전

원문의 의미·확신 정도를 유지하며 문장과 순서만 정돈한다. 추가 사실은 아래 보충에 둔다.

### 멘토의 보충과 교정

원문에서 빠진 조건이나 잘못 연결한 부분을 근거와 함께 기록한다. 사용자가 이 내용을 자기 말로 확인했는지도 구분한다.

## 연결된 지식

실제로 존재하는 공통 개념·프로젝트 적용·세션 노트에 상대 링크를 넣는다. “선수 지식 / 함께 쓰임 / 비교 / 적용 사례 / 다음 학습” 중 관계와 이유를 한 문장으로 적는다. 여러 프로젝트에서 같은 개념을 배우면 이 노트를 재사용한다.

[전체 학습 지도](../maps/learning-map.md)에 현재 주제를 연결하고 실제 평가에 맞춰 준비 자료·학습 중·이해 확인을 표시한다.

## 남은 질문과 확인 상태

아직 실행하지 않음. 관련 세션과 실험을 진행하면 연결한다.
