# 학습 세션

## 대상 업무와 범위

프로젝트 ID·경로(또는 공통 개념 모드), 학습 주제와 실제 구현 요청 여부를 구분한다. 순수 개념 학습에서 업무·코드가 없으면 이유와 함께 not-applicable로 기록한다.

## 처음 궁금했던 점

사용자가 알고 싶은 개념·흐름과 왜 궁금했는지를 실제 대화에서 기록한다. 이전에 답한 내용을 반복해서 묻지 않는다.

## 질문을 주고받으며 이해한 흐름

필요성·동작 원리·요청 및 데이터 흐름·다른 개념과의 차이, 사용자의 후속 질문을 연결한다. 실제 코드·문서와 설계안·멘토 해석·미검증 가정을 구분한다.

## 내가 이해한 내용 — 사용자 원문

사용자가 자기 말로 정리하기를 기다리는 중이다. 문장·목록·비유 모두 가능하며 실제 표현과 대화 출처를 보존한다. 멘토가 사용자의 설명을 대신 만들어 넣지 않는다.

## 의미를 유지해 다듬은 표현

사용자 원문의 의미·확신 정도를 유지하며 문장·순서만 정리한다. 새 사실이나 오류 수정은 멘토 보충에 분리한다.

## 멘토 보충과 아직 헷갈리는 점

맞게 연결한 부분, 빠진 조건·핵심 오해, 필요한 설명과 남은 질문을 적는다. 수정한 내용을 사용자가 자기 말로 다시 확인했는지는 별도로 기록한다. 이전 답변도 남긴다.

## 프로젝트와 기존 개념 연결

어느 코드·설정·업무 규칙·설계 선택과 연결되는지 적고 기존 개념·프로젝트 적용·세션에 상대 링크를 둔다. [전체 학습 지도](../maps/learning-map.md)도 갱신한다.

## 실제 검증 여부

기본은 미실행이다. 실험을 사용자가 선택해 실제로 수행한 경우에만 방법·환경·관찰·한계를 추가한다. 개념 이해와 실제 실행 검증을 구분한다.

## 개발 범위와 승인

제품 개발 전달을 요청한 경우에만 기술·업무·코드 이해와 범위·승인 기록을 연결한다. 일반 개념 대화와 노트 정리에 구현 승인을 요구하지 않는다. 실제 승인이 없으면 미승인으로 둔다.

## 관련 노트와 다음 질문

중복 설명 대신 관련 개념 노트·코드·명세·평가 파일을 연결한다.

각 개념이 이번 코드 흐름에서 하는 역할을 한 문장으로 적고 [전체 학습 지도](../maps/learning-map.md)를 갱신한다. 이전·다음 세션이 실제로 있을 때만 연결한다. 문서 생성과 사용자 이해도 확인을 구분한다.
