# 학습 세션

## 대상 업무와 범위

프로젝트 ID·경로(또는 공통 개념 모드), 학습 주제와 실제 구현 요청 여부를 구분한다. 순수 개념 학습에서 업무·코드가 없으면 이유와 함께 not-applicable로 기록한다.

## 이번에 얻을 기술 능력

수업이 끝나면 직접 추적·작성·수정할 수 있을 구체적인 목표 하나와 확인할 결과를 적는다. 필요한 업무 규칙을 연결한다.

## 원리 설명과 코드 추적

새로 배운 원리·문법, 실제 파일·메서드, 입력값이 인자·객체·출력으로 바뀌는 과정을 기록한다. 현재 이해 확인에 대한 기존 답변을 활용한다.

## 보충 설명과 재질문

답변 후 필요한 설명과 다른 조건의 질문을 기록한다. 이전 답변도 남긴다.

## 직접 작성한 부분과 실험

실습 파일·실행 환경·재현 명령, 멘토가 제공한 골격, 학습자가 작성한 핵심 코드와 받은 힌트를 구분한다. 실습이 없으면 미실행으로 둔다.

| 상황 | 실행 전 예상 | 실제 관찰 | 차이의 이유 |
| --- | --- | --- | --- |
| 이번 과제의 입력·조건 | 사용자 예상 대기 | 미실행 | 아직 확인하지 않음 |

## 변형 과제와 다음 단계

조건을 하나 바꾼 과제, 학습자의 독립 해결 여부·필요한 도움, 다음에 보충할 부분을 적는다. 실행 성공만으로 이해도 통과를 표시하지 않는다.

## 개발 범위와 승인

아직 구현 범위를 확정하지 않았고 사용자 승인이 없다. 통과 후 제시한 범위와 사용자 승인 원문·시각·출처를 연결한다.

## 관련 노트와 다음 질문

중복 설명 대신 관련 개념 노트·코드·명세·평가 파일을 연결한다.

각 개념이 이번 코드 흐름에서 하는 역할을 한 문장으로 적고 [전체 학습 지도](../maps/learning-map.md)를 갱신한다. 이전·다음 세션이 실제로 있을 때만 연결한다. 문서 생성과 사용자 이해도 확인을 구분한다.
