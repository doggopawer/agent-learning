# Obsidian Notes

이 `SKILL.md`의 심볼릭 링크를 해석한 실제 디렉터리를 `S`, `S/../../..`의 실제 경로를 공통 학습 작업공간 `W`로 정한다. 현재 프로젝트가 아니라 `W/AGENTS.md`, `W/projects.json`, `W/notes/index.md`를 읽는다. 이번 호출의 프로젝트 ID·경로 또는 공통 개념 모드를 확인하며 직접 호출만 있고 대상이 없으면 현재 프로젝트를 선택한다. 필요하면 형제 스킬의 `W/.agents/skills/learning-mentor/scripts/session_context.py`로 현재 프로젝트를 확인·등록한다. 출력은 항상 `W/notes`와 `W/records`에만 둔다. 원본 프로젝트의 `docs`는 참고 자료다. 이 스킬은 직접 호출하거나 명시적으로 시작한 멘토 학습 세션에서 사용한다.

## 생성·갱신

1. 공통 개념은 `notes/concepts/`, 실제 적용은 `notes/projects/<project-id>/`에서 기존 노트를 찾는다. 같은 이름의 주제라도 다른 프로젝트 파일을 덮어쓰지 않는다. [개념 연결과 지도 규칙](references/knowledge-links.md)에 따라 공통 개념·프로젝트 사례·세션을 의미 있는 상대 링크로 연결한다. 코드 경로·심볼과 관련 PRD·ADR을 직접 읽고, 현재 사실·설계 근거·멘토의 해석을 나눈다. 이전 대화 내용을 추측하지 않는다.
2. [입력 형식](references/note-format.md)에 따라 `records/notes/<project-id>/<slug>.json` (공통 개념은 `records/notes/concepts/<slug>.json`)을 작성하거나 갱신한다. 사용자 필기와 답변은 별도 세션에 그대로 보존한다.
3. `python3 "S/scripts/notes.py" upsert --input "W/records/notes/<project-id>/<slug>.json"`을 실행한다. `S`, `W`는 확인한 절대 경로로 바꾸며 공통 개념 입력은 `concepts/`를 사용한다. 주제 노트의 생성 영역만 갱신한다. 생성 영역이 없거나 손상된 기존 문서는 덮어쓰지 말고 병합 위치를 검토한다.
4. `notes/sessions/<project-id>/` (공통 개념은 `notes/sessions/concepts/`)에 실제 질문·답변·보충 설명·남은 질문을 기록하고 주제 노트로 연결한다. 기본 시각 지도인 `notes/maps/learning-map.canvas`와 `notes/maps/learning-map.md`의 관계별 링크·학습 상태를 현재 세션과 함께 갱신한다. 기존 카드 ID·사용자 배치를 보존하고 관련 가지만 추가·수정한다. `notes/index.md`에 새 노트나 주제 지도를 연결한다. 기존 기록을 반복 복사하지 않는다.
5. `notes.py check`로 경로·심볼·소스 지문을 확인한다. 원본 변경을 발견하면 노트 내용과 평가 영향을 검토한 뒤 갱신한다. 파일이 같다는 이유로 내용의 정확성까지 보장됐다고 표현하지 않는다.

실습 세션에는 기술 목표·추적한 값·학습자가 작성한 부분·실행 전 예상·실제 결과·차이의 이유·변형 과제와 도움의 정도를 남긴다. 실제 실습 파일과 재현 명령을 연결하고, 멘토가 작성·실행한 결과를 학습자의 독립 구현으로 표시하지 않는다. `W/labs/`는 보관함 밖의 학습 파일이므로 파일 링크와 작업공간 기준 경로를 적으며, 원본 소스용 `sources` 필드의 프로젝트 경로를 우회해 등록하지 않는다. 생성기 입력은 기존 필드를 사용하고 상세 실습 기록은 세션에 둔다.

## 기록 기준

- 프로젝트 노트에는 필요성, 기술 흐름, 비즈니스 규칙, 실제 코드 경로·심볼, 설계 근거, 복습 질문을 넣는다. 코드 언어에 제한을 두지 않는다. 설계 문서가 없으면 없다고 적고 추론은 해석으로 표시한다. 공통 개념에는 적용 조건·예시·한계와 복습 질문을 적고 확인한 출처 및 프로젝트 사례를 연결한다. 실제 코드가 없는데 코드 검증 완료라고 기록하지 않는다. 코드 발췌는 필요한 부분만 사용한다.
- 최초 학습 상태는 `learning`, 실험 상태는 `not-run`이다. 생성기가 이해 완료를 자동 표시하지 않는다. 멘토가 실제 대화 근거로 통과시킨 경우에만 해당 속성을 수동 갱신하고 세션으로 연결한다.
- 단순 설명 요청도 노트 생성은 가능하지만 제품 구현이나 원본 파일 변경의 승인으로 해석하지 않는다.
- 기존 설계 문서의 “검증 완료”와 이번 대화에서 직접 실행한 검증을 구분한다. 실제 실행하지 않은 결과를 만들어 넣지 않는다.
- 보관함 내부는 상대 Markdown 링크를 사용한다. 원본 코드는 보관함 밖에 있으므로 파일 링크와 저장소 기준 경로·심볼·해시를 함께 남긴다. 외부 코드 파일이 Obsidian 그래프의 내부 노트가 된다고 설명하지 않는다.
- 생성 영역 밖의 사용자 필기는 보존한다. 원문에 비밀·실제 고객 정보가 있으면 기록에서 제외한다. 다른 채팅 자동 수집, 자동 발송, 플러그인 설치는 이 스킬의 범위가 아니다.
